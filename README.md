# polymarket

This is a limit order book matching engine in C++20, written against the polymarket-base benchmark. The benchmark replays a 1M-operation mixed trace of limit submits, market submits, cancels, and modifies, then checks every result and fill against expected output. Each side of the book keeps an array of price levels covering prices 0 to 2000. Each level is a FIFO intrusive linked list of nodes drawn from a preallocated order pool that reuses freed slots, and prices outside that range fall back to a binary heap. A boost `unordered_flat_map` maps live order ids to their place in the book for cancel and modify, and a boost `unordered_flat_set` holds every id ever submitted so duplicates get rejected.

Most of the work after correctness was performance tuning. I profiled with the Instruments Time Profiler and checked each change with paired A/B runs. `ab.sh` builds a before and an after binary and runs them for 20 blocks of 5 reps in shuffled order. In late October the heap version took 147 ms on mixed 1M. Moving the id map to boost's flat map and presizing tables cut that to about 76 ms. Replacing the heap with price-level lists got it to about 61 ms, 3.6x faster than the benchmark's C++ baseline at 218 ms, and a stub engine showed that about 11 ms of that is the harness itself. Smaller wins came after. Cancel now does one hash lookup instead of two, worth 3.4%. Exposing hot path function bodies in headers so the compiler could inline them, plus cutting string copies, took replay from about 60 ms to 52 ms. Reserving room for 4 fills on an order's first match took it from 51.23 ms to 49.65 ms, a ratio of 0.966, faster in 19 of 20 blocks. What remains is mostly unlinking orders and hashing ids, which looks like the real cost of this workload rather than overhead, so I parked the project at about 49.6 ms.
